# DevMania interactive experience release

## Delivered

- Session experience engine: project/category exploration, achievements and discovery flags. Session storage contains public IDs and flags only; free-text ideas and contact details are not persisted.
- Public conceptual X-Ray for all 13 registry entries. Planned projects are labeled as in development. Capability buttons open the filtered Universe.
- Three isolated simulations: Trackora shipment journey, Assia Padel court selection and confirmation, Pineville stay dates and reservation summary. No production records, payments or bookings are created.
- Challenge DevMania: a business-problem flow using POST /api/challenge with server-side OpenAI access, bounded structured-output validation, existing project-ID validation, timeout handling and editable contact handoff.
- Universe: category/capability filtering, project previews, pointer pan, zoom/reset/exit and accessible project list. Narrow screens start with the list and can show the graph.
- DNA: actual registry counts and project evidence, including clear published/in-development labels. No proficiency percentages. SaaS has zero entries until verified classification is supplied.
- Time Machine: dated chronology and slider support, with undated projects displayed separately. Currently no verified dates are in the registry, so no dates or chronology are invented.
- Three conceptual 60-second build stories, with pause, next-step and restart. Reduced-motion preference starts them paused.
- MANIA navigation hub, idea/problem entry points, search/filtering, Universe and DNA.
- Surprise Me avoids unseen-project repeats until the eligible collection is exhausted and avoids immediate repeats afterward.
- Four subtle session achievements, with a 15-second toast cooldown.
- Classified project unlocks through three project explorations and Developer Mode; it never exposes a private resource.

## Security and configuration

Existing runtime environment names only: OPENAI_API_KEY (secret), OPENAI_MODEL (text). No new credentials or setup required.

OpenAI receives an explicitly selected user input and sanitized public portfolio context, not arbitrary extra request fields. API output is rendered as text. Public API routing preserves origin, request-size and rate checks. Analytics use fixed event names and selected metadata keys; no full idea/problem text is sent to analytics. Terminal input is parsed only against fixed handlers; unknown/restricted commands receive the specified access-denied message. Server/private files are excluded from asset serving. Browser JavaScript required to operate the public website remains inherently inspectable; no private project source or repository links are served.

## Limits and deliberate deferrals

- Chronological timeline remains pending verified project dates.
- Destinotel and Beautify playgrounds are deferred as specified in favor of three initial demos.
- Public metadata retains the existing approved portfolio descriptions/status; factual corrections should be made in the central registry.
- AI requires available account credit/model access and can fail or time out; a clearly labeled editable fallback remains available.
- Existing in-memory per-instance rate limiting is retained; it is not an account-wide hard spending cap.
- Analytics events are emitted to an existing dataLayer if present and as DOM events; this release does not configure an external analytics account.
